# COFA 서술형 사전 대비

사용자가 요청한 사전 연습에서만 사용한다. 서술형 실전 응시 중에는 출제·답변 지원을 진행하지 않는다. 프로젝트를 읽기 전용으로 조사하고 질문과 피드백은 대화에서만 전달한다. 코드, 문서, 설정을 수정하거나 연습 상태를 파일에 저장하지 않는다.

## SET — 질문 출제

1. 대상 프로젝트의 실제 코드와 루트의 `DEFENSE_LOG.md`를 읽는다. 설계 변경, AI 제안 확인 또는 검증 경위를 더 알아야 할 때 관련 `WORKLOG.md`를 읽는다. 로그가 없거나 내용이 코드와 다르면 그 한계를 표시하고 확인 가능한 주제만 사용한다. 읽을 코드나 확인된 코드 위치가 없으면 필요한 범위를 알려주고 출제를 보류한다.
2. 진입점부터 실제로 호출되는 함수와 데이터·상태 변경을 따라간다. 실제 코드에 나타난 알고리즘 선택, 기록된 대안과 그 근거, 실패 조건에서 일어나는 동작을 질문 후보로 삼는다. 계획과 실행의 경계, retry, fallback 등은 해당 동작이 코드에 있을 때만 다룬다. 설계 이유나 검증 결과는 코드에서 추정하지 않고 기록과 대조한다.
3. 각 질문을 구체적인 함수, 입력, 상태 전이 또는 예외 상황에 연결하고, 질문을 내기 전에 근거가 되는 `파일:줄`을 직접 열어 확인한다. 근거가 확인되지 않는 질문은 제외한다.
4. 질문과 확인한 코드 위치를 **한 번에 하나만** 제시한다. 정답, 모범답안, 코드 위치가 입증하는 동작에 대한 설명은 사용자가 답하기 전에는 공개하지 않는다. 현재 질문에 대한 사용자의 답을 기다린다.

## JUDGE — 사용자 답변 검증

1. 현재 질문에 대한 사용자의 실제 답변을 받은 뒤 검증한다. 답변이 없으면 기다리고, 의미가 불명확하면 해당 질문에 대한 보충 설명을 하나 요청한다.
2. 질문의 코드 위치와 관련 호출부를 다시 확인하고, 답변의 주장과 실제 코드의 동작을 대조한다. 설계 이유, 대안, 승인, 실행 결과는 확인된 로그·검증 근거와 따로 대조한다.
3. 잘못 이해한 부분과 답변에 빠진 핵심을 구분해 관련 `파일:줄`과 함께 짚는다. 로그나 실행 증거가 부족한 주장은 미확인으로 표시한다. 답이 근거와 일치하면 그렇게 알려준다. 사용자를 대신해 답변을 완성하거나 점수를 계산하지 않는다.
4. 현재 답변에 대한 피드백을 마친 뒤 연습을 계속할 때 다음 질문을 하나 제시한다. 보충 답변이 필요하면 현재 질문에 머문다.
